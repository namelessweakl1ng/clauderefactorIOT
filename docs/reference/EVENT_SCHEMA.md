# Canonical event schema

Every `trapsig-events-*` document is ECS-inspired and contains:

```json
{"@timestamp":"2026-01-01T12:00:00Z","event":{"id":"unique","category":"authentication","type":"info","action":"login_attempt","outcome":"failure"},"source":{"ip":"192.0.2.20","port":41234},"destination":{"ip":"192.0.2.10","port":2222},"network":{"transport":"tcp","protocol":"ssh"},"service":{"name":"cowrie"},"honeypot":{"id":"cowrie-01","type":"ssh_telnet"},"observer":{"name":"trapsig-pi","type":"honeypot_sensor"},"trapsig":{"sensor_id":"pi-01"},"message":"Failed login"}
```

`event.category` is one of `authentication`, `network`, `web`, `process`, or `session`; `event.type` uses `connection`, `start`, `end`, `info`, or `error`; outcome is `success`, `failure`, or `unknown`. Protocol details belong only below controlled `ssh`, `http`, `mqtt`, `cowrie`, `authentication`, `process`, or `url` objects. IDs must be stable and unique. Times are UTC ISO-8601. Parse failures retain the original record in `trapsig-dead-letter-*`.

Authentication events may contain `authentication.username` and `authentication.password` from deliberately submitted honeypot credentials. HTTP requests use `http.request.method`, `http.user_agent`, and `url.path`. IoT records use `iot.operation`. MQTT records use `mqtt.operation`, `mqtt.packet_type`, and, when present, `mqtt.client_id`, `mqtt.topic`, `mqtt.packet_id`, `mqtt.qos`, `mqtt.flags`, and `mqtt.remaining_length`. These controlled namespaces are retained through Logstash so session and rule processing consumes the exact indexed contract.

## Integrity contract (schema version 1)

All newly normalized events carry `trapsig.schema_version: "1"`. Historical records
without it remain readable. `@timestamp` is the honeypot-reported UTC occurrence time;
`event.ingested` is a separate UTC timestamp generated by Logstash when normalization
runs (it is never copied from occurrence time).

The required canonical fields are `@timestamp`, `event.id`, `event.category`,
`event.type`, `event.action`, `event.outcome`, `source.ip`, `destination.ip`,
`network.transport`, `network.protocol`, `service.name`, `honeypot.id`,
`honeypot.type`, `trapsig.sensor_id`, and `trapsig.schema_version`. Optional ports and
MQTT packet types are integers. The controlled values remain: categories
`authentication`, `network`, `web`, `process`, `session`; types `connection`, `start`,
`end`, `info`, `error`; and outcomes `success`, `failure`, `unknown`.

`trapsig.internal` identifies loopback sources (`127.0.0.0/8` or `::1`), with
`trapsig.internal_reason: "loopback_source"`. Private laboratory sources such as
`192.168.50.20` are not internal. Raw internal events remain immutable in
`trapsig-events-*`, but processor sessionization/detection and security analytics
exclude both newly classified records and legacy records identifiable by loopback IP.

Invalid JSON retains its exact input line at `raw.original`; invalid canonical events retain the parsed `raw` object. Both receive
`trapsig.dead_letter_reason`, and route only to `trapsig-dead-letter-YYYY.MM.dd`.
Inspect them with `curl 'localhost:9200/trapsig-dead-letter-*/_search?pretty'`.

Composable templates in `elk/elasticsearch/index-templates/` define mappings for
`trapsig-events-*`, dead letters, sessions, detections, and experiments. They set one
shard and zero replicas for the single-node lab. Compatibility multi-fields preserve the historical `severity.keyword`, `type.keyword`, and `honeypots_touched.keyword` aggregation paths. The idempotent setup job also sets zero replicas on existing, known TRAPSIG indices without recreating them. Dated raw indices (`trapsig-events-*`, `trapsig-dead-letter-*`, `trapsig-network-*`) carry the
`trapsig-retention` ILM policy (default 30-day delete; edit `elk/elasticsearch/ilm/trapsig-retention.json`).
Experiments and other derived indices are never automatically deleted; export datasets before raw events age out.

Historical loopback-derived sessions/detections are not removed automatically. Preview
an exact, derived-index-only cleanup with:

```
python -m backend.app.tools.cleanup_internal_derived
python -m backend.app.tools.cleanup_internal_derived --confirm
```

The command never targets raw event or experiment indices.

## Schema version 2 (persona runtime)

Decision record: [ADR-0003](../adr/0003-event-schema-v2.md). v2 is **additive**:
every v1 field keeps its name and meaning, and readers must tolerate both
versions. Records from persona containers carry `raw.schema_version: 2` and are
indexed with `trapsig.schema_version: "2"`; Cowrie and the legacy decoys stay "1".

| Field | Meaning |
| --- | --- |
| `network.transport` | `tcp` or `udp`, reported by the sensor (v1 hard-coded `tcp`; anything else is dead-lettered as `invalid_network_transport`) |
| `network.community_id` | Community ID v1 over (source, sensor IP, **published** port, transport), the same value Zeek emits |
| `destination.port` | the **published** host port (e.g. 502), not the container port |
| `persona.{id,name,device_type,vendor,model,firmware}` | the device identity that produced the event |
| `trapsig.connection_id`, `trapsig.sequence` | per-connection identifier and message order (multi-turn protocols) |
| `trapsig.plugin`, `trapsig.interaction` | emitting protocol plugin and its interaction level |
| `trapsig.reply_suppressed` | `rate_limited` / `amplification_cap` when the UDP guard withheld a reply |
| `trapsig.payload_excerpt` | first `logging.payload_bytes` bytes of the message (stored, not indexed) |
| `http.response.status_code` | HTTP/RTSP response code where applicable |

Controlled protocol namespaces (only these keys are ever copied; the Logstash
whitelist and `backend/app/services/normalizer.py::V2_NAMESPACES` are
parity-tested):

* `modbus`: transaction_id, unit_id, function_code, function, address, quantity, value, exception_code, write, hardening_blocked, mei_type, read_device_id_code, object_id, response_length
* `coap`: version, type, code, method, message_id, token_length, uri_path, uri_query, content_format, payload_length, option_count, response_code, state_change, error, length
* `rtsp`: method, uri, path, cseq, auth_scheme, transport, body_length, status_code
* `ftp`: command, argument, reply_code, data_channel_refused
* `dns`: id, opcode, recursion_desired, qname, qtype, qclass, rcode, error
* `ssdp`: method, target, st, man, mx
* `hardening`: actions, decision_id
* `process`: command_line
* `s7`: function, function_code, write, identify, area, address, szl_id, hardening_blocked
* `bacnet`: service, property, object, write, identify, hardening_blocked
* `enip`: command, cip_service, write, identify
* `atg`: command, write, identify, hardening_blocked
* `snmp`: version, community, pdu, oids, write, error
* `redis`: command, args, write, exploit
* `sip`: method, to_user, from_user, user_agent, auth_user, error
* `tftp`: opcode, filename, mode, error
* `vnc`: client_version, security_type
* `rdp`: cookie_user, requested_protocols

FTP and other passwords live only in `authentication.password`.

Sessions additionally carry `personas`, `transports`, `community_ids` (at most 500)
and `connection_count`.

## Network observations (`trapsig-network-*`)

Zeek `conn`/`dns`/`http`/`ssl` JSON records are normalized by
`elk/logstash/pipelines/30-zeek.conf` into a **separate** daily index. They never
enter `trapsig-events-*`, sessions or experiment correlation. `event.id` is the
SHA-256 of the original line (idempotent replays), `event.dataset` is
`zeek.<log>`, and Zeek fields live under `zeek.*`. `dns`/`http`/`ssl` records inherit
their conn record's Community ID through `zeek.uid` at query time.

## New derived indices

`trapsig-sensor-instances` (latest heartbeat per sensor and persona),
`trapsig-personas` (immutable persona versions), `trapsig-rule-state`
(rule activation overrides), `trapsig-audit`, `trapsig-model-anomaly`,
`trapsig-comparisons`. Large opaque structures (forest trees, comparison engine
reports, persona definitions, detection `signals`) are stored with
`enabled: false`: they are kept in `_source` but never mapped.
